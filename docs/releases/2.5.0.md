# LexRunner 2.5.0 durable operations and bounded continuity release

Status: release candidate. Signed-tag publication, the public npm record, and a clean registry
consumer proof remain pending until the release workflow completes.

This minor release adds durable gate-operation handles and retained-evidence inspection, while
hardening the repository, profile, package, and reporting boundaries used by the existing
integration workflow. It does not grant execution, merge, deployment, or release authority.

## What changes

- CLI `gate start/status/cancel` and MCP `gates.start/status/cancel` provide explicit durable gate
  operations. Frozen candidate identity, idempotent admission, receipts, status, and cooperative
  cancellation survive an observer disconnect; missing or stale worker observations remain unknown
  and never trigger automatic replay.
- Status surfaces can read back bounded retained artifacts after verifying their explicit identity.
  Changed, missing, or incomplete evidence remains visibly incomplete and cannot establish merge
  eligibility.
- Plan creation, gate execution, dry runs, status, snapshots, and resume paths bind to the selected
  repository and physical worktree. Unsafe search qualifiers, cross-repository mismatches,
  ambiguous artifact paths, and unsupported executable multi-repository plans fail before side
  effects.
- Blank-repository initialization now creates schema-valid configuration while preserving authored
  standard and enterprise files unless `--force` is explicit. Protected, malformed, missing, or
  changing profiles fail closed across the CLI and both MCP adapters.
- The local dogfood installer and merge-weave helper retain exact source/runtime evidence, preserve
  shell argument boundaries, invalidate stale reports, propagate failed previews or execution, and
  bind successful reports to the target in the validated Plan.

## Coordination foundations

The source tree now includes durable worker dispatch, observation, reconciliation, evidence
snapshots, structured receipts, and bounded human-question/answer evidence for ADR-010
coordination. Native Windows boundary and recovery work adds protocol, lifecycle, and failure
qualification evidence.

These foundations remain bounded application or qualification evidence. LexRunner 2.5.0 does not
enable a public headless launcher, production native host, trusted human signer, autonomous retry,
or a new authority path. Worker and human-host observations remain claims until the owning verifier
accepts them under the applicable protected policy.

## Compatibility

- The package still requires Node.js 24 or newer and exact `@smartergpt/lex@4.0.3`.
- Package exports, the `lexrunner` and `lex-pr` executable names, and Plan Schema 1.0.1 remain
  compatible.
- The published MCP inventory grows additively from 34 to 37 MCP tools with
  `gates.start/status/cancel`.
- Deprecated 2.x compatibility surfaces keep their documented 3.0.0 removal schedule.

## Evidence and limits

The candidate's implementation changes passed exact-head independent review and hosted CI before
source merge. The release commit receives a separate exact-head review, complete local release
gates, and hosted CI before tagging. Package byte totals are telemetry; the package boundary still
enforces its content allowlist, forbidden paths, required runtime assets, manifest/bin identities,
and bounded file count.

Point-in-time profile and filesystem checks prevent accidental stale sharing but do not provide
native custody against a hostile same-principal process. Gate names, successful initialization,
guidance, previews, receipts, and observed artifacts remain non-authorizing.

## Publication

The signed `v2.5.0` tag must target the exact owner-signed release commit reviewed and contained in
`main`, not the release PR merge commit. The stable GitHub workflow then reruns the release gates,
publishes through npm OIDC with the `latest` dist-tag, and creates the GitHub release. Until that
workflow, the npm registry, and a clean native Windows consumer agree, this document records a
candidate rather than proof of public availability.
